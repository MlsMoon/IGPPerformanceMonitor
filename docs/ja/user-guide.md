## 1. 必要なもの

- Windows 10 または 11、64 ビット
- **管理者**権限、または *Performance Log Users* グループ
- ゲームや対象アプリが起動済み（または起動してから **プロセス一覧を更新**）
- GPU %、VRAM、電力、温度が欲しい場合は NVIDIA（NVML）推奨。他社 GPU でも PresentMon 経由のフレームタイムと FPS は取れます

アプリは [Intel PresentMon](https://github.com/GameTechDev/PresentMon) 2.4.1 と Windows ETW を使うため、昇格が必要です。未昇格ならすべての入口で UAC が出ます。

## 2. インストールと初回起動

### インストーラ

1. [Releases](https://github.com/MlsMoon/IGPPerformanceMonitor/releases/latest) から `IGPPerformanceMonitor-Setup-x.y.z.exe` をダウンロードします。
2. インストーラを実行します（UAC）。Program Files へ入り、スタートメニューにショートカットが付きます。
3. **IGP Performance Monitor** を起動し、求められたら UAC を許可します。

### ポータブル EXE

ポータブル版は任意のフォルダで `IGPPerformanceMonitor.exe` を実行します。自動昇格しない場合は右クリック → **管理者として実行**。

`auto_updater.exe` は内部ヘルパーです。手で起動しないでください。

パッケージ版は起動から約 1.5 秒後に、新しいリリースがあるか GitHub を静かに確認します。

## 3. 最初のキャプチャ

1. ゲームや対象アプリを先に起動し、プロセス一覧に出るようにします。
2. 左の **プロセス選択** パネルで必要なら検索します。
3. 1 つ以上の名前（例: `game.exe`）を選び、**▶** をクリックするかダブルクリックします。
4. 任意: **自動停止（秒）**。`0` は手動停止まで続けます。
5. **キャプチャ開始** または **F5**。
6. プレイします。統計表とチャートを見ます。監視中の各ウィンドウにオーバーレイが出ます。
7. **停止**、またはもう一度 **F5**。

監視リストは保存され、次回起動時に復元されます。まだ起動していない名前でも問題ありません。PresentMon はフレーム提示を待ちます。

GUI では少なくとも 1 つのプロセスが必要です。マシン上の全プロセスを取るのは[ヘッドレス](#14-ヘッドレス--コマンドライン)の `--all-processes` だけです。ライブ UI には向きません。

セッションが 0 フレームで終わると警告が出ます。名前が違うか、対象が描画していません。

## 4. メインウィンドウ

### レイアウト

| 領域 | 役割 |
|---|---|
| 左パネル | 検索、利用可能なプロセス、監視リスト、開始 / 停止、自動停止タイマ |
| 右側上部 | システムチップ（CPU、GPU、RAM、ディスプレイ）とライブ統計表 |
| チャート格子 | 指標ごとに 1 枚。FPS が表示中なら先頭行を横断します |
| ステータスバー | 準備完了 / キャプチャ中 / エラー、フレーム数と経過時間 |

### メニュー

- **ファイル** — キャプチャ開始/停止、CSV 読み込み、CSV 書き出し
- **表示** — チャートごとの表示、チャートパネル、ダークモード、常に最前面、オーバーレイ表示/非表示、クリックスルー
- **ヘルプ** — ショートカット、ユーザーマニュアル、更新確認、バージョン履歴（ロールバック）、変更履歴、GitHub、バージョン情報

キャプチャ中は検索、追加/削除、タイマがロックされます。監視リストを変えるときは先に停止してください。

## 5. ライブ統計

表は **設定したすべてのアプリ** を出します。まだフレームがない名前は薄くなり「フレームなし」と出ます。ランチャーか、ロード画面のままかもしれません。

よく見る項目:

| 統計 | 意味 |
|---|---|
| フレーム | このセッションで受け取ったフレーム数 |
| 平均 FPS | 有効な FPS サンプルの平均 |
| 1% Low | 最も遅い 1% のフレームを FPS で表す（ソートした FPS の P99） |
| 5% Low | 最も遅い 5%（P95） |
| 最小 / 最大 | 最悪と最良の FPS |
| 平均 FT | フレームタイムの平均 |
| 平均 CPU / GPU / メモリ / VRAM | そのアプリのセッション平均 |

画面上の FPS **チャート** は軽い EMA をかけ、上限なし FPS のちらつきを抑えます。**CSV は生値のままです。** レポートを書くときは CSV を正にしてください。

## 6. チャート

### チャート一覧

| チャート | 内容 |
|---|---|
| FPS | アプリ別フレームレート（画面上は EMA） |
| フレームタイム | `1000 / fps`（ミリ秒、EMA なし） |
| CPU | アプリ CPU % にシステム合計の曲線を重ねる |
| CPU コア | 論理コアごとに 1 本、太線が平均 |
| アプリ CPU コア | 使用コア数（コアあたり `cpu% / 100`） |
| メモリ | アプリのワーキングセット（MB） |
| システム RAM | マシン全体の使用メモリ（GB） |
| GPU | アプリ GPU % にシステム合計を重ねる（NVIDIA） |
| アプリ VRAM | プロセス別 VRAM（MB、NVML） |
| GPU 電力 | ボード電力（W） |
| GPU 温度 | GPU 温度（°C） |
| VRAM % | ボード全体の VRAM 使用率 |

### 表示と非表示

表示 / 非表示:

- **表示 → チャート**
- 画面内の **チャートパネル**（`Ctrl+J`）
- カードを右クリック → **非表示**

各カードは **最大化**、**復元**、**自動サイズ** ができます。表示状態は `%APPDATA%\IGPPerformanceMonitor\config.json` に保存されます。GPU バックエンドがない環境では GPU / VRAM / 電力 / 温度は最初から隠れます。

格子はウィンドウ幅に合わせて 1〜4 列に組み直します。1080p ではチャートを隠さず、スクロール領域に置きます。

欠測は空白（`None`）です。ダミーの `-1` は使いません。

## 7. オーバーレイ

### 表示内容

キャプチャ開始で、監視中アプリごとに最前面オーバーレイが 1 つ付きます。そのアプリのメインウィンドウ左上付近に置き、約 30 fps で追従します。対象を最小化すると隠れます。

各オーバーレイ: アプリ名、FPS（EMA）、フレームタイム、アプリメモリ、アプリ CPU（使用コア）、アプリ GPU、システム VRAM %、システム CPU。

### 操作

| 操作 | 方法 |
|---|---|
| 全オーバーレイの表示 / 非表示 | **F9** または 表示 → オーバーレイの表示/非表示 |
| クリックスルー | 表示 → クリックスルー。マウスはゲームへ通ります。以降オーバーレイのコンテキストメニューは使えません。表示メニューを使ってください |
| 1 つ閉じる | オーバーレイを右クリック（クリックスルー中は無効） |

追跡は、そのプロセスで最も大きく、可視で、タイトルのある非ツールウィンドウを選びます。Unity エディタ、ブラウザ、パネルの多い IDE では、フロート検査器ではなくメインビューに付きやすいです。

## 8. テーマとウィンドウ

- **Ctrl+D** または 表示 → **ダークモード** でダーク / ライト切替。Windows のネイティブタイトルバーも追従します。
- **Ctrl+T** または 表示 → **常に最前面** でメインウィンドウを固定します。
- スプリッタ幅（サイド対チャート、統計対チャート）とウィンドウ位置は次回起動で復元されます。

## 9. CSV 書き出し

フレームがある状態で **ファイル → CSV を書き出す…** または **Ctrl+E**。

選択肢:

- **すべてのフレーム** — 1 ファイル
- **プロセスごと** — アプリごとに 1 ファイルをフォルダへ
- ヘッダを含めるか
- 末尾に要約を付けるか（平均 / 最小 / 最大 / 1% Low / 5% Low、アプリ CPU とメモリ）

エンコーディングはシステムの既定です。先頭のコメント行に CPU / GPU / RAM / ディスプレイ、監視リスト、書き出し時刻が入ります。

書き出される FPS は **生値** で、画面上の EMA ではありません。

## 10. CSV 読み込みとオフライン分析

**ファイル → CSV を読み込む…** または **Ctrl+I**。インポータは複数のエンコーディングを試します。

分析ウィンドウは 4 タブです。

| タブ | 内容 |
|---|---|
| Performance | 生の FPS とフレームタイム |
| System / Process Metrics | ファイル内の CPU、メモリ、GPU、VRAM |
| Stutter | 固定 33.3 ms / 50 ms スパイクと、直近ベースラインの約 2 倍の動的スパイク |
| Data Quality | 各指標が実際に埋まっている行の割合 |

以前のセッションやヘッドレスキャプチャを、PresentMon を再実行せずに見直せます。

## 11. 更新とロールバック

### 更新の確認

**パッケージ済み EXE** のみです。ソース実行では自己更新しません。

- 起動直後に最新 GitHub Release の `app_manifest.json` を取得します。
- **ヘルプ → 更新を確認…** で同じ確認を即座に実行します。
- ダウンロードは SHA256 検証のあと、`auto_updater.exe` が EXE を差し替えて再起動します。

### ロールバック

- **ヘルプ → バージョン履歴** で、保存済みなら直前の公開版へ戻せます。

開発モードでは自己更新不可と出ます。想定どおりです。

オブジェクトストレージ経由で更新を出さないでください。経路は GitHub Releases のみです。

## 12. UI 言語

UI は `en` と `zh_CN` の 2 つだけです。

1. 環境変数 **`IGP_LANG`** が最優先（`en` または `zh_CN`）。
2. それ以外で、Windows ロケールが `zh` で始まれば簡体字中国語。
3. それ以外は英語。

メニューに言語項目はありません。ショートカットかシェルで設定します。

```bat
set IGP_LANG=zh_CN
IGPPerformanceMonitor.exe
```

```bat
set IGP_LANG=en
python -m src.main
```

`docs/zh-TW` と `docs/ja` は文書だけです。UI は変わりません。

## 14. ヘッドレス / コマンドライン

ウィンドウなし。同じキャプチャパイプラインで CSV を書きます。

### パッケージ版

パッケージ版:

```bat
IGPPerformanceMonitor.exe --headless --process-name game.exe --timed 30 -o C:\captures\run.csv
```

### ソース実行

ソース（UAC 後も `temp\` に書くならヘルパーを推奨）:

```bat
Scripts\capture_debug.bat --process-name Unity.exe --timed 10
```

### 引数

| 引数 | 意味 |
|---|---|
| `--headless` | UI なしで CSV へ（`--capture-debug` は旧別名） |
| `--process-name` | 繰り返し可。例: `--process-name game.exe --process-name Discord.exe` |
| `--process-id` | 繰り返し可能な PID |
| `--exclude` | 繰り返し可能な除外名 |
| `--all-processes` | マシン上の全プレゼンタ（うるさい。GUI では使わない） |
| `--timed N` | 秒。`0` は Ctrl+C まで |
| `-o` / `--output` | CSV パス。既定は `temp\igpmon-<アプリ>-<タイムスタンプ>.csv` |
| `--debug` | 詳細ログ（`igp_debug.log`） |
| `--no-track-display` / `--no-track-input` / `--no-track-gpu` | 該当する PresentMon トラッカを切る |

ヘッドレスで `--timed` を省略すると既定は **5 秒** です。

## 15. 設定とログ

| 項目 | 場所 |
|---|---|
| ユーザー設定 | `%APPDATA%\IGPPerformanceMonitor\config.json` |
| 更新状態 / バックアップ | 同じ AppData フォルダ |
| デバッグログ（開発 / `--debug` / ヘッドレス） | リポジトリまたは EXE 横の `temp\igp_debug.log` |

`config.json` にはテーマ、チャート表示、ウィンドウとスプリッタ、オーバーレイのクリックスルー、監視プロセス、自動停止秒数が入ります。BOM なし UTF-8 です。削除すると設定がリセットされます（初回起動時、古いレジストリ値から一部が復元されることがあります）。

## 16. 指標用語

| 用語 | 定義 |
|---|---|
| FPS | present 間隔が有効なとき `1000 / MsBetweenPresents` |
| フレームタイム | present 間のミリ秒 |
| 1% Low / 5% Low | ソートした FPS の第 1 / 5 パーセンタイル（悪いフレームほど低い FPS） |
| アプリ CPU % | そのプロセスのマシン占有率（psutil、約 500 ms サンプリング。フレームごとではない） |
| アプリ CPU コア | おおまかな使用コア数 |
| 合計 CPU / 合計 GPU | マシン全体の使用率 |
| アプリ GPU % | NVML のプロセス別使用率。合計 GPU を短時間超えることがあります（API が違う）。NVML に値がなければ、オーバーレイは PresentMon のビジー時間推計に落ちることがあります |
| アプリ VRAM | そのプロセスの NVML `usedGpuMemory` |
| VRAM % | ボード全体の使用量 / 総量 |
| GPU 電力 / 温度 | NVML のボードセンサ。スナップショットのみ。CSV の毎行には書きません |
| Present モード | アプリの提示方法（例: Hardware: Independent Flip） |
| Dropped | PresentMon のドロップフラグ |
| Click-to-photon / PC latency | 該当トラッカがオンのときの PresentMon 遅延列 |

システム CPU / GPU / RAM は **約 500 ms のサンプラスレッド** から刻印されます。フレームごとに `cpu_percent()` を呼ぶと、Windows では `0` になります。FPS の画面曲線は CSV より滑らかに見えることがあります。EMA は UI だけです。
