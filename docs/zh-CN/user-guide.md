## 1. 运行条件

- Windows 10 或 11，64 位
- **管理员**权限，或加入「Performance Log Users」组
- 游戏或目标程序已经在运行（或先启动，再点 **刷新进程列表**）
- 需要 GPU %、显存、功耗、温度时，建议 NVIDIA（NVML）。其他显卡仍可通过 PresentMon 得到帧时间与帧率

程序使用 [Intel PresentMon](https://github.com/GameTechDev/PresentMon) 2.4.1 和 Windows ETW，因此必须提权。所有入口在未提权时都会弹出 UAC。

## 2. 安装与首次启动

### 安装包

1. 从 [Releases](https://github.com/MlsMoon/IGPPerformanceMonitor/releases/latest) 下载 `IGPPerformanceMonitor-Setup-x.y.z.exe`。
2. 运行安装程序（UAC）。默认装到 Program Files，并添加开始菜单快捷方式。
3. 启动 **IGP Performance Monitor**。若再次提示 UAC，请允许。

### 便携版

便携版：把 `IGPPerformanceMonitor.exe` 放到任意目录。若没有自动提权，右键 → **以管理员身份运行**。

`auto_updater.exe` 是内部助手，不要手动打开。

打包版启动约 1.5 秒后会静默检查 GitHub 上是否有新版本。

## 3. 第一次采集

1. 先启动游戏或目标程序，让它出现在进程列表里。
2. 左侧 **进程选择** 面板可按名称搜索。
3. 选中一个或多个进程（例如 `game.exe`），点 **▶**，或双击名称。
4. 可选：**自动停止（秒）**。`0` 表示一直采到你手动停止。
5. 点 **开始采集** 或按 **F5**。
6. 正常游玩。看统计表和图表。每个被监视窗口上会出现叠加窗。
7. 点 **停止** 或再按一次 **F5**。

监视列表会保存，下次启动自动恢复。进程还没启动也没关系，PresentMon 会等它开始呈现帧。

图形界面必须至少添加一个进程。监视整台机器上所有进程只在[无界面模式](#14-无界面--命令行)可用（`--all-processes`），不适合实时界面。

若本次一帧都没有，程序会提示：进程名可能不对，或目标并没有在渲染。

## 4. 主窗口

### 布局

| 区域 | 作用 |
|---|---|
| 左侧面板 | 搜索、可用进程、监视列表、开始 / 停止、自动停止计时 |
| 右侧上方 | 系统信息条（CPU、GPU、内存、显示器）和实时统计表 |
| 图表网格 | 每个指标一张卡片。FPS 可见时占第一整行 |
| 状态栏 | 就绪 / 采集中 / 错误，以及帧数与已用时间 |

### 菜单

- **文件** — 开始/停止采集、导入 CSV、导出 CSV
- **视图** — 各图表显隐、图表面板、深色模式、窗口置顶、叠加窗显隐、点击穿透
- **帮助** — 快捷键、用户手册、检查更新、版本历史（回退）、更新日志、GitHub、关于

采集进行中会锁定搜索、添加/移除和计时器。要改监视列表请先停止。

## 5. 实时统计

表格列出 **所有已配置的应用**，不只是已经出过帧的。还没有帧的名称会变灰并显示「无帧」——可能是启动器，或游戏还在加载。

常见项：

| 统计 | 含义 |
|---|---|
| 帧数 | 本次会话收到的帧 |
| 平均 FPS | 有效 FPS 样本的均值 |
| 1% Low | 最慢的 1% 帧，以 FPS 表示（排序后 FPS 的 P99） |
| 5% Low | 最慢的 5%（P95） |
| 最小 / 最大 | 最差与最好 FPS |
| 平均帧时间 | 帧时间均值 |
| 平均 CPU / GPU / 内存 / 显存 | 该应用本会话平均值 |

界面上的 FPS **曲线**会做轻度 EMA，避免解锁帧率时闪得厉害。**CSV 导出仍是原始值。** 写报告时请以 CSV 为准。

## 6. 图表

### 图表一览

| 图表 | 内容 |
|---|---|
| FPS | 分应用帧率（屏幕上为 EMA） |
| 帧时间 | `1000 / fps`，毫秒（不做 EMA） |
| CPU | 应用 CPU %，并叠加整机曲线 |
| CPU 核心 | 每个逻辑核一条曲线，粗线为平均 |
| 应用 CPU 核心 | 占用的核心数（按每核 `cpu% / 100`） |
| 内存 | 应用工作集（MB） |
| 系统内存 | 整机已用内存（GB） |
| GPU | 应用 GPU %，并叠加整机（NVIDIA） |
| 应用显存 | 分进程显存（MB，NVML） |
| GPU 功耗 | 整卡功耗（W） |
| GPU 温度 | GPU 温度（°C） |
| 显存 % | 整卡显存占用 |

### 显示与隐藏

显示或隐藏：

- **视图 → 图表**
- 界面内的 **图表面板**（`Ctrl+J`）
- 在卡片上右键 → **隐藏**

每张卡片可 **最大化**、**还原**、**自适应**。显隐状态保存在 `%APPDATA%\IGPPerformanceMonitor\config.json`。没有 GPU 后端时，GPU / 显存 / 功耗 / 温度默认隐藏。

网格随窗口宽度重排（1–4 列）。1080p 下图表在滚动区域内，不会为了「塞下」而默认藏起来。

缺测是空白（`None`），不会写成 `-1`。

## 7. 叠加窗

### 显示内容

开始采集后，每个监视中的应用会有一个置顶叠加窗，贴在该应用主窗口左上角附近并跟随（约 30 fps）。目标最小化时叠加窗会隐藏。

每个叠加窗显示：应用名、FPS（EMA）、帧时间、应用内存、应用 CPU（及占用核心）、应用 GPU、整机显存 %、整机 CPU。

### 操作

| 操作 | 方法 |
|---|---|
| 隐藏 / 显示全部叠加窗 | **F9** 或 视图 → 显示/隐藏叠加窗 |
| 点击穿透 | 视图 → 点击穿透。鼠标落到游戏上。此后叠加窗右键菜单不可用，请改用视图菜单 |
| 关闭单个叠加窗 | 在叠加窗上右键（开启穿透时无效） |

跟踪逻辑会选该进程最大的、可见的、有标题的非工具窗口。Unity 编辑器、浏览器、带很多面板的 IDE 一般会跟主视图，而不是浮动检查器。

## 8. 主题与窗口

- **Ctrl+D** 或 视图 → **深色模式** 切换深浅色。Windows 原生标题栏会一起变。
- **Ctrl+T** 或 视图 → **窗口置顶** 钉住主窗口。
- 分割条宽度（侧栏 vs 图表、统计 vs 图表）和窗口位置会在下次启动恢复。

## 9. 导出 CSV

有数据后：**文件 → 导出 CSV…** 或 **Ctrl+E**。

选项：

- **全部帧** — 一个文件
- **按进程** — 每个应用一个文件，放到选定文件夹
- 是否包含表头
- 是否在文件末尾附加汇总（平均 / 最小 / 最大 / 1% Low / 5% Low，以及应用 CPU 与内存）

编码使用系统默认。文件顶部的注释行记录 CPU / GPU / 内存 / 显示器、监视列表和导出时间。

导出的 FPS 是 **原始值**，不是屏幕上的 EMA。

## 10. 导入 CSV 与离线分析

**文件 → 导入 CSV…** 或 **Ctrl+I**。导入会尝试多种编码。

分析窗口四个标签：

| 标签 | 内容 |
|---|---|
| Performance | 原始 FPS 与帧时间 |
| System / Process Metrics | 文件中的 CPU、内存、GPU、显存 |
| Stutter | 固定 33.3 ms / 50 ms 尖峰，以及相对近期基线约 2 倍的动态尖峰 |
| Data Quality | 各指标实际有多少行有值 |

用来回看上次会话或无界面采集，不必再跑 PresentMon。

## 11. 更新与回退

### 检查更新

仅 **打包后的 EXE** 可用，从源码运行没有自我更新。

- 启动后不久会拉取最新 GitHub Release 上的 `app_manifest.json`。
- **帮助 → 检查更新…** 可立即再查一次。
- 下载会做 SHA256 校验，再由 `auto_updater.exe` 替换 EXE 并重启。

### 回退

- **帮助 → 版本历史** 可回退到上一份已保存的发布版（如果有）。

开发模式会提示无法自我更新，这是正常的。

不要通过对象存储发更新。唯一渠道是 GitHub Releases。

## 12. 界面语言

界面只有两种：`en` 和 `zh_CN`。

1. 环境变量 **`IGP_LANG`** 优先（`en` 或 `zh_CN`）。
2. 否则，Windows 区域若以 `zh` 开头则用简体中文。
3. 其余情况为英语。

菜单里没有语言开关。可在快捷方式或命令行里设置：

```bat
set IGP_LANG=zh_CN
IGPPerformanceMonitor.exe
```

```bat
set IGP_LANG=en
python -m src.main
```

`docs/zh-TW`、`docs/ja` 只是文档，不会改界面语言。

## 14. 无界面 / 命令行

没有窗口。同一套采集管线，写出 CSV。

### 安装版

已安装的打包版：

```bat
IGPPerformanceMonitor.exe --headless --process-name game.exe --timed 30 -o C:\captures\run.csv
```

### 源码

源码（优先用脚本，UAC 之后仍写入 `temp\`）：

```bat
Scripts\capture_debug.bat --process-name Unity.exe --timed 10
```

### 参数

| 参数 | 含义 |
|---|---|
| `--headless` | 采集到 CSV，无界面（`--capture-debug` 是旧别名） |
| `--process-name` | 可重复。例：`--process-name game.exe --process-name Discord.exe` |
| `--process-id` | 可重复的 PID |
| `--exclude` | 可重复，排除的进程名 |
| `--all-processes` | 机器上所有在呈现的进程（很吵；不要在 GUI 里这么干） |
| `--timed N` | 秒数。`0` 表示直到 Ctrl+C |
| `-o` / `--output` | CSV 路径。默认 `temp\igpmon-<应用>-<时间戳>.csv` |
| `--debug` | 更详细日志（`igp_debug.log`） |
| `--no-track-display` / `--no-track-input` / `--no-track-gpu` | 关闭对应 PresentMon 跟踪 |

无界面模式下省略 `--timed` 时默认 **5 秒**。

## 15. 设置与日志

| 项目 | 位置 |
|---|---|
| 用户设置 | `%APPDATA%\IGPPerformanceMonitor\config.json` |
| 更新状态 / 备份 | 同一 AppData 目录 |
| 调试日志（开发 / `--debug` / 无界面） | 仓库或 EXE 旁的 `temp\igp_debug.log` |

`config.json` 保存主题、图表显隐、窗口与分割条、叠加窗穿透、监视列表和自动停止秒数。UTF-8 无 BOM。删掉即可重置（首次运行可能从旧注册表项迁回一部分值）。

## 16. 指标术语

| 术语 | 定义 |
|---|---|
| FPS | 在 present 间隔有效时为 `1000 / MsBetweenPresents` |
| 帧时间 | 两次 present 之间的毫秒数 |
| 1% Low / 5% Low | 排序后 FPS 列表的第 1 / 5 百分位（更差的帧，更低的 FPS） |
| 应用 CPU % | 该进程占整机的份额（psutil，约 500 ms 采样，不是每帧采一次） |
| 应用 CPU 核心 | 大约占用了几个核 |
| 整机 CPU / 整机 GPU | 整机利用率 |
| 应用 GPU % | NVML 分进程利用率。可能短暂高于整机 GPU——两套 NVIDIA API。NVML 没数时，叠加窗可能退回 PresentMon 忙碌时间估算 |
| 应用显存 | 该进程的 NVML `usedGpuMemory` |
| 显存 % | 整卡已用 / 总量 |
| GPU 功耗 / 温度 | NVML 整卡传感器。只在快照里，不会写进每一行 CSV |
| Present 模式 | 应用如何呈现（例如 Hardware: Independent Flip） |
| Dropped | PresentMon 丢帧标记 |
| Click-to-photon / PC latency | 打开对应跟踪时的 PresentMon 延迟列 |

整机 CPU / GPU / 内存来自 **约 500 ms 的采样线程**。若每帧调用 `cpu_percent()`，在 Windows 上会读到 `0`。FPS 的界面曲线可能比 CSV 更平滑，因为只有 UI 使用 EMA。
